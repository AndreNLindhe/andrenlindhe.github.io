1. Tre verktyg, tre jobb

Kursen använder tre verktyg. De gör olika saker, och blandar du ihop dem är det lätt att tro att du lämnat in när du inte har det.

VerktygVad ligger där
itslearningUppgifterna, guiderna, planeringen, deadlines och din återkoppling. Här lämnar du in.
GitHubDin kod. Ditt repo, dina commits och senare din publicerade sajt.
CodespacesDär du skriver koden. VS Code som körs i webbläsaren.
Meningen att komma ihåg

Koden till GitHub, länken till itslearning.

Inlämningen är alltså inte en fil. Den är en adress. Det betyder att adressen måste fungera för någon annan än dig – annars finns det ingenting att sätta betyg på.

2. Konto och eget repo

Kontot

  1. Gå till github.com och välj Sign up. Har du redan ett konto: Sign in.
  2. Välj ett användarnamn du kan säga högt. Det kommer synas i adressen till din sajt under hela kursen.
  3. Verifiera mejladressen. GitHub skickar ett mejl – klicka på länken i det.

Utan verifierad mejladress går Codespaces inte att starta. Hittar du inte mejlet, titta i skräpposten.

Repot

Ett repo (kortform för repository) är mappen med ditt projekt, som GitHub håller reda på åt dig. Du gör din egen kopia av kursens startmapp:

  1. Öppna github.com/AndreNLindhe/webbutveckling1-start.
  2. Klicka på knappen Use this template och välj Create a new repository.
  3. Skriv webbutveckling1 som namn.
  4. Under Choose visibility: kontrollera att det står Public. Det är förvalt – rör det bara om det står något annat.
  5. Klicka Create repository.

Låt reglaget Include all branches stå kvar på Off. Du behöver bara huvudgrenen.

Varför publikt?

Ett privat repo syns bara för dig. Länken du lämnar in ger 404 för alla andra. Det ser rätt ut från din sida, eftersom du är inloggad – och därför är det så lätt att missa.

Valde du Private av misstag: Settings → General → skrolla längst ned till Danger Zone → Change repository visibility → Make public. GitHub ber dig skriva repots namn för att bekräfta.

Prova själv

Öppna din repo-länk i ett privat fönster, där du inte är inloggad. Syns sidan är repot publikt. Får du 404 är det fortfarande privat.

3. Öppna ditt Codespace

Ett Codespace är en färdig utvecklingsmiljö som körs på GitHubs datorer. Du får VS Code i webbläsaren, kopplat till ditt repo. Ingenting behöver installeras.

  1. Gå till ditt repo på github.com.
  2. Klicka på knappen Code.
  3. Välj fliken Codespaces.
  4. Klicka Create codespace on main.

Första gången tar det en till två minuter. Det ser ut som att ingenting händer. Klicka inte igen – då startar du två Codespaces och kan hamna i fel miljö nästa gång.

När det öppnat ser du filerna i listan till vänster. Klicka på index.html för att öppna den.

Nästa gång du ska arbeta

Samma väg: Code → Codespaces → klicka på det Codespace som redan finns i listan. Skapa inte ett nytt varje gång, då ligger dina ändringar kvar i det gamla.

4. Ändra och spara

Öppna index.html och leta upp rubriken:

<h1>Din rubrik här</h1>

Byt ut texten mellan taggarna mot ditt eget namn:

<h1>Ada Lovelace</h1>

Du behöver inte förstå HTML än – det kommer i område 2. Just nu ska ändringen bara bevisa att hela kedjan fungerar, från din webbläsare till GitHub. Spara med Ctrl + S.

Commit och push

En commit är en sparad punkt i historiken, med ett meddelande om vad du gjorde. En push skickar dina commits upp till GitHub.

  1. Klicka på ikonen med tre grenar i vänsterkanten – Source Control.
  2. index.html står under Changes. Håll muspekaren över filen och klicka +.
  3. Skriv ett meddelande i rutan högst upp, till exempel Bytte rubrik till mitt namn.
  4. Klicka Commit.
  5. Klicka Sync Changes.

Utan meddelande vägrar VS Code att committa. Det är med flit. Meddelandet ska säga vad du gjorde – update säger ingenting, och begripliga commit-meddelanden är ett krav i alla inlämningar i kursen.

Steg 5 är det som faktiskt skickar upp ändringen. Hoppar du över det ser allt klart ut i VS Code medan GitHub fortfarande är tomt.

Prova själv

Gå tillbaka till ditt repo på github.com och ladda om sidan. Står ditt namn där? Då har hela kedjan fungerat.

5. Lämna in

  1. Stå på ditt repos sida på github.com och ladda om, så du ser att ändringen finns.
  2. Kopiera adressen ur adressfältet. Den ska se ut så här:
https://github.com/dittanvandarnamn/webbutveckling1
  1. Gå till itslearning → kursen Webbutveckling 1 → uppgiften Kom igång.
  2. Klistra in länken och lämna in.
Kolla adressen

Den ska börja med github.com/. Innehåller den github.dev, codespaces eller ett slumpmässigt namn med bindestreck har du kopierat länken till ditt Codespace – och den fungerar bara för dig.

Så här går varje inlämning till resten av kursen. Samma två steg, varje gång: din kod ligger uppdaterad och pushad på GitHub, och länken till ditt publika repo lämnas i itslearning-uppgiften senast fredag 23:59.

9. Ta det längre

För dig som är klar och vill fortsätta. Ingenting av det här krävs för uppgiften.

  • Läs historiken. På ditt repo, klicka på Commits. Varje commit går att öppna och visar exakt vilka rader som ändrades, i grönt och rött. Gör ytterligare två ändringar och titta på hur historiken byggs upp.
  • Skriv en README.md. Filen med det namnet visas automatiskt på repots framsida. Skriv vad projektet är. Den är din sajts anslagstavla resten av kursen.
  • Arbeta lokalt. Codespaces är inte enda vägen. Installera VS Code och Git på din egen dator och klona repot med git clone. Samma repo, samma commits, men utan att vara beroende av nätet.

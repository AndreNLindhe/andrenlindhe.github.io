1. Vad JavaScript gör

Hittills har din kod varit något: HTML säger vad som finns, CSS hur det ser ut. JavaScript är webbens programmeringsspråk, och det gör något när någon använder sajten. Det körs i webbläsaren, på besökarens dator, och det reagerar på det som händer på sidan: ett klick, en tangent, ett fält som fylls i.

Klicka på lägesknappen i referensprojektet. Det låter, och färgerna byts. Öppna sedan sidkällan med Ctrl + U och leta upp knappen. Det enda på knappen som har med ljudet att göra är ett attribut, data-ljud="vaxla". HTML kan inte spela ett ljud när någon klickar, och CSS kan det inte heller. Det gör en tredje sorts fil.

En modul är en färdig bit kod som gör en sak och går att koppla in i en sajt som inte byggdes för den. Ljudmodulen spelar ljud. Den vet ingenting om fyrar.

JavaScript har ingenting med språket Java att göra, bara namnet. Det valdes för att Java var populärt 1995.

Ljudmodulen

Hela filen, skript/ljud.js. Läs den en gång utan att försöka förstå allt. Lägg märke till att den är kort. Resten av avsnittet går igenom den, ett begrepp i taget.

// Ljudmodulen. Spelar ett ljud när något händer med ett element som har
// attributet data-ljud. Värdet är filnamnet utan .mp3:
//   <button data-ljud="vaxla">
// Utan något annat är det ett klick. data-ljud-nar väljer en annan händelse:
//   <input data-ljud="klart" data-ljud-nar="change">
// Ändra inställningarna nedan. Resten behöver du inte röra.

// Inställningar
const LJUDMAPP = "ljud/";  // var ljudfilerna ligger, räknat från sidan
const VOLYM = 0.5;         // 0 är tyst, 1 är fullt

// Spelar filen som heter namn. Gör ingenting om ljudet är avstängt.
function spela(namn) {
  if (document.documentElement.classList.contains("ljud-av")) {
    return;
  }
  const ljud = new Audio(LJUDMAPP + namn + ".mp3");
  ljud.volume = VOLYM;
  ljud.play();
}

// Hitta alla element med data-ljud och lyssna efter händelsen på vart och ett.
const ljudelement = document.querySelectorAll("[data-ljud]");

for (const element of ljudelement) {
  let handelse = "click";
  if (element.dataset.ljudNar) {
    handelse = element.dataset.ljudNar;
  }
  element.addEventListener(handelse, function () {
    spela(element.dataset.ljud);
  });
}

Kommentarer

Rader som börjar med // är till för människor. Webbläsaren hoppar över dem. Det är samma sak som /* */ i CSS och <!-- --> i HTML, fast för en rad i taget. Läs de sex första raderna: de säger vad modulen gör, hur den styrs från HTML:en och vad du får ändra.

Variabel: const och let

En variabel är ett namn på ett värde.

const VOLYM = 0.5;         // 0 är tyst, 1 är fullt

En text inom citattecken kallas en sträng, engelska string. VOLYM är ett tal, och tal står utan citattecken. Skriver du "0.5" är det en sträng som råkar innehålla siffror.

Längre ned i filen står let. Det är en variabel vars värde får bytas. Använd const när värdet inte ska bytas och let när det ska. Det gamla ordet var används inte i kursen; det står i uppgiftens tekniska krav.

En variabel är som en variabel i CSS. --accent är ett namn på en färg, och ändrar du värdet på ett ställe slår det igenom överallt. Här är det mappen och volymen.

Funktion, parameter och anrop

En funktion är några rader med ett namn, som körs när någon anropar namnet.

function spela(namn) {
  if (document.documentElement.classList.contains("ljud-av")) {
    return;
  }
  const ljud = new Audio(LJUDMAPP + namn + ".mp3");
  ljud.volume = VOLYM;
  ljud.play();
}
  • function spela(namn) – en funktion som heter spela. namn inom parentesen är en parameter: en tom plats som fylls i när funktionen anropas.
  • Klamrarna { } håller ihop det som hör till funktionen, som i CSS.
  • new Audio(LJUDMAPP + namn + ".mp3") skapar ett ljud ur en fil. + sätter ihop strängar: "ljud/" och "vaxla" och ".mp3" blir "ljud/vaxla.mp3".
  • const ljud = … sparar ljudet i en variabel, så att nästa rad kan använda det.
  • ljud.volume = VOLYM; ger ljudet volymen från inställningen.
  • ljud.play(); spelar det.

Att skriva en funktion och att anropa den är två olika saker. Raderna ovan spelar ingenting när sidan laddas. De väntar tills någon skriver namnet med parenteser efter, ett anrop:

spela("vaxla");

Just då är namn lika med "vaxla", och funktionen spelar ljud/vaxla.mp3.

Villkor

De tre första raderna i funktionen är ett villkor:

  if (document.documentElement.classList.contains("ljud-av")) {
    return;
  }

Läs det som en mening: om html-elementet har klassen ljud-av, sluta här.

  • if betyder om. Det som står inom parentesen är frågan, och det som står inom klamrarna körs bara om svaret är ja.
  • document.documentElement är sidans html-element, samma som :root i CSS.
  • classList.contains("ljud-av") frågar om elementet har den klassen. Svaret är true eller false, sant eller falskt.
  • return betyder gå ut ur funktionen. Raderna under körs då aldrig, och det blir tyst.
Ingenting i referensprojektet sätter ljud-av

Villkoret väntar på en ljudknapp som sätter klassen ljud-av på html. Den knappen skriver du själv. Det är ett bör-krav, nivå C, i Projekt 5. Vad den behöver står i avsnitt 4.

Loop och händelse

Sista delen hittar elementen och lyssnar på dem.

const ljudelement = document.querySelectorAll("[data-ljud]");

querySelectorAll hittar alla element som matchar en selektor, och selektorn skrivs som i CSS: [data-ljud] är alla element som har attributet data-ljud. Variabeln ljudelement blir en lista över dem. Hur det går till står i avsnitt 2.

for (const element of ljudelement) {
  let handelse = "click";
  if (element.dataset.ljudNar) {
    handelse = element.dataset.ljudNar;
  }
  element.addEventListener(handelse, function () {
    spela(element.dataset.ljud);
  });
}
  • for (const element of ljudelement) är en loop: gör det som står inom klamrarna en gång för varje element i listan. Varje varv heter elementet element.
  • let handelse = "click"; är en variabel med let, eftersom värdet kanske byts på nästa rad. Varje element börjar med klick.
  • Det andra villkoret: om elementet har attributet data-ljud-nar, byt händelse till det som står där. Saknas attributet är villkoret inte uppfyllt, och det blir klick.
  • addEventListener betyder lägg till en lyssnare. En händelse, engelska event, är något som händer på sidan. En event listener, händelselyssnare, väntar på en händelse och kör en funktion när den kommer.
  • function () { … } är funktionen som körs när händelsen kommer. Den har inget namn, eftersom den bara behövs här.
  • element.dataset.ljud läser värdet i data-ljud. På lägesknappen är det "vaxla".

dataset läser attribut som börjar med data-. Prefixet tas bort, bindestrecken försvinner och bokstaven efter ett bindestreck blir stor:

Följ ett klick

Lägesknappen har data-ljud="vaxla" och inget data-ljud-nar. Så här går ett klick, med ljudmodulen bredvid dig:

  1. När sidan laddas går loopen ett varv för knappen. handelse blir "click", och en lyssnare läggs på knappen.
  2. Någon klickar. Lyssnarens funktion körs.
  3. Den anropar spela("vaxla").
  4. Villkoret: har html klassen ljud-av? Nej, så funktionen fortsätter.
  5. new Audio skapar ett ljud ur "ljud/vaxla.mp3", volymen sätts till 0.5, och play() spelar det.
Loopen körs en gång, lyssnaren varje gång

Loopen körs en gång, när sidan laddas. Den sätter upp lyssnarna. Det som står inuti lyssnaren körs först när någon klickar, och sedan varje gång någon klickar. Det är områdets svåraste tanke. Koden läses inte bara uppifrån och ned en gång.

Hela modulen styrs alltså från HTML:en. Vilket ljud står i data-ljud, när i data-ljud-nar. Filen behöver du inte öppna för att använda den.

2. DOM och konsolen

Ljudmodulen använder querySelectorAll och classList. Båda arbetar med något som har ett namn: DOM, sidan som webbläsaren håller i minnet medan den visas. Det är den JavaScript läser och ändrar, aldrig HTML-filen.

Filen och trädet

Öppna Elements-fliken i DevTools, F12, dubbelklicka på texten i sidans h1 och skriv något annat. Rubriken ändras direkt. Ladda om, och den är tillbaka. Du ändrade inte filen, du ändrade webbläsarens kopia av sidan.

DOM står för Document Object Model, dokumentobjektsmodellen. När webbläsaren läser HTML-filen bygger den upp sidan som ett träd av element: html överst, head och body under det, header, main och footer under body, och så vidare nedåt. Ett element är en del av trädet, till exempel en knapp eller en rubrik.

  • Ett element som ligger inuti ett annat är dess barn. nav är barn till header.
  • Elementet utanför är förälder. header är förälder till nav.
  • Samma ord som i CSS, där header > p betyder ett p som är barn till header.

Jämför lägesknappen på två ställen. Ctrl + U visar filen, som den ligger på disken, och där står hidden på knappen. Elements-fliken visar trädet, och där står inget hidden. Ett skript har ändrat trädet efter att filen lästes; vilket står i avsnitt 4. Elements-fliken visar alltså DOM som den ser ut just nu. Sidkällan visar hur sidan såg ut när den kom.

querySelector och querySelectorAll

Skriv i konsolen på referensprojektet, en rad i taget, och tryck Enter efter varje:

document.querySelector("h1");

document är hela sidan. querySelector hittar det första elementet som matchar selektorn, och selektorn skrivs precis som i CSS, inom citattecken. Konsolen svarar med elementet. Håll musen över svaret, så lyser elementet upp på sidan.

document.querySelectorAll("nav a");

querySelectorAll hittar alla. Svaret är en lista, och siffran visar hur många. Det är den raden ljudmodulen använder, med "[data-ljud]".

document.querySelector(".finns-inte");

Svaret är null, som betyder ingenting. Ingen varning, inget fel, bara tomt. Ordet kommer tillbaka i ett felmeddelande i avsnitt 3.

Ändra texten

document.querySelector("h1").textContent = "Fyrar i hela Sverige";

textContent är elementets text. Med = byts den ut, samma = som sätter en variabel.

Det här är ändringen som betyder mest i området.

document.documentElement.classList.add("morkt");

Hela sajten blir mörk. classList är elementets klasser, och add lägger till en. JavaScript ändrade inga färger. Det satte en klass, och färgerna fanns redan i CSS:en och väntade på den.

Varför inget onclick i HTML:en

Det finns ett äldre sätt, och du kommer att hitta det när du söker på nätet:

<!-- Fungerar, men blandar beteende och struktur -->
<button type="button" onclick="spela('vaxla')">Mörkt läge</button>

Det fungerar, och det är ändå förbjudet i Projekt 5, som ska-krav. Tre skäl:

  • Tre språk på ett ställe. HTML ska säga vad som finns. Här säger den också vad som händer, och JavaScript står i ett attribut där ingen letar efter det.
  • Varje element för hand. Ska tio knappar låta står samma kod tio gånger. Ljudmodulen hittar alla element med data-ljud själv, i en loop.
  • Ett ställe att ändra. Byter du händelse eller volym ändrar du en rad i en fil, inte varje sida.

data-ljud="vaxla" är information: vilket ljud. onclick är beteende. Informationen får stå i HTML:en, beteendet hör hemma i .js-filen. Samma sak gäller onload, onchange och alla andra attribut som börjar på on.

Fältet: JavaScript byter klass, CSS rör

Öppna rapportera.html i referensprojektet. Skriv Vinga i fältet Fyrens namn. Ingenting händer medan du skriver. Tryck Tab. Fältets kant blir grön, och en stapel syns till vänster. Töm fältet och tabba ut igen, så försvinner stapeln. Det hände när fältet lämnades, och bara för att det var rätt ifyllt.

Koden är skript/falt.js, inkopplad bara på den sidan:

// Ett obligatoriskt fält visar att det är rätt ifyllt när man lämnar det.
// Hur det ser ut står i stil.css under .godkant. Här byts bara klassen.
const obligatoriska = document.querySelectorAll("input[required]");

for (const falt of obligatoriska) {
  falt.addEventListener("change", function () {
    if (falt.checkValidity()) {
      falt.classList.add("godkant");
    } else {
      falt.classList.remove("godkant");
    }
  });
}
  • querySelectorAll("input[required]") hittar alla fält med attributet required. På sidan är det två: namnet och e-posten.
  • Loopen sätter en lyssnare på vart och ett, som i ljudmodulen.
  • "change" i stället för "click": lyssnaren körs när fältet lämnas efter en ändring.
  • falt.checkValidity() frågar webbläsaren om fältet uppfyller sina regler: att det är ifyllt, och för e-posten att adressen har rätt form. Svaret är true eller false.
  • if … else: om svaret är sant, lägg till klassen. Annars, ta bort den. else betyder just annars.

Hur klassen ser ut står i stil.css, avsnitt 10, inte i skriptet:

/* Fältet är rätt ifyllt. En stapel till vänster, inte bara färg, så att det syns
   också för den som inte skiljer färgerna åt. Värdena kommer ur överlämningen. */
input.godkant {
  border-color: var(--klar);
  box-shadow: inset 0.3rem 0 0 var(--klar);
  transition: border-color 150ms ease-out, box-shadow 150ms ease-out;
}

@media (prefers-reduced-motion: reduce) {
  input.godkant {
    transition: none;
  }
}

--klar är en variabel i :root, en grön. box-shadow med inset ritar stapeln innanför kanten. transition och prefers-reduced-motion skrev du i område 5, på knappen; syntaxen är densamma, bara med två egenskaper. Se guiden till område 5, avsnitt 3. Varför 150 ms och ease-out tog Gränssnittsdesign den 25 februari; här är det värden som står i en överlämning.

CSS rör, JavaScript byter läge

Skriptet vet inte att fältet blir grönt. Det vet bara att klassen heter godkant. Vill du att stapeln ska vara blå ändrar du CSS:en och rör inte skriptet. Så ska all rörelse och allt utseende i Projekt 5 byggas: utseendet i en klass i CSS, och JavaScript som sätter och tar bort klassen. Aldrig style direkt från skriptet.

Referensprojektet har också input:invalid, som ger en röd kant utan en rad JavaScript. Det nya är att JavaScript kan sätta ett tillstånd som CSS inte kan räkna ut själv, här rätt ifyllt och lämnat.

Ljudmodulen spelar ett ljud varje gång händelsen kommer. Ett ljud som bara ska spelas ibland, till exempel när ett fält är fel ifyllt, klarar den inte. Då är det egen händelsekod som anropar spela på rätt ställe i ett villkor som det här. Det är C-nivå, och mer står i avsnitt 6.

Klick och tangentbord

Tabba till lägesknappen och tryck Enter. Färgerna byts och det låter. Tryck mellanslag, samma sak. Lyssnaren säger "click", och ingen klickade. En button gör om Enter och mellanslag till ett klick av sig själv.

En div med samma lyssnare gör det inte. Den går inte ens att tabba till, som i guiden till område 5, avsnitt 5. Regeln: lyssna på klick på en button eller en a, aldrig på en div, så fungerar tangentbordet utan en rad extra kod.

Vill du lyssna på tangenterna själva finns keydown. Skriv i konsolen och tryck sedan på några tangenter:

document.addEventListener("keydown", function (event) {
  console.log(event.key);
});

Konsolen skriver a, Enter, Escape. event är en parameter, som namn i ljudmodulens funktion. Webbläsaren fyller den med uppgifter om händelsen, och event.key är vilken tangent det var. keydown behövs sällan i Projekt 5. Den som använder button har tangentbordet gratis.

Din första skriptfil

En knapp som gör något synligt, på en sida i din egen sajt. Fyra delar, i den här ordningen. Först knappen i HTML:en, någonstans i main:

<button class="prova-knapp" type="button">Markera innehållet</button>

type="button" gör att knappen inte skickar något formulär den råkar stå i. Sedan läget i stil.css, alltså hur det ser ut när klassen är satt:

}

Välj gärna något annat som syns: en bakgrund, en kant, en annan textfärg. Skapa sedan mappen skript/ bredvid index.html, och filen prova.js i den:

// Övning: knappen växlar en klass på main. Hur det ser ut står i stil.css.

Läs ett felmeddelande

När knappen fungerar, framkalla ett fel med flit. Den som aldrig sett felet med flit blir rädd för det första gången det kommer på riktigt.

  1. Stava fel på klassen i skriptet: ".prova-knap". Spara, ladda om och öppna konsolen.
  2. Läs det röda. Chrome och Edge skriver det första nedan, Firefox det andra.
Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')

Uncaught TypeError: provknapp is null

Läs det bakifrån:

  • null – något var ingenting. Samma null som konsolen svarade i avsnitt 2.
  • reading 'addEventListener' – det var när koden försökte lägga till en lyssnare.
  • Till höger står filnamnet och radnumret, prova.js:5. Klicka på det, så visar konsolen raden.

Stavfelet står på rad 2, men felet står på rad 5. Felet står inte på raden där det gick fel, utan på raden där felet märktes. Det var på rad 5 som null skulle användas. Rätta stavningen och ladda om, så är felet borta.

Ta sedan bort defer på script-raden och ladda om. Samma fel, fast klassen är rätt stavad. Förklaringen står i avsnitt 4. Sätt tillbaka defer.

Två saker ger inget fel alls, bara tystnad. Ett felstavat händelsenamn, "onclick" eller "Click", och en klass som heter olika i CSS:en och i classList. Titta i Elements-fliken om klassen faktiskt sätts när du klickar. Syns den där men inte på sidan är det CSS:en.

Ett vanligt misstag till: att anropa funktionen i stället för att lämna över den.

// Fel: spelar ljudet en gång när sidan laddas, och sedan aldrig mer

// Rätt: det som ska hända vid klicket ligger inuti function () { … }
provknapp.addEventListener("click", function () {
  spela("vaxla");
});

Ljudfilen som saknas

Ett fel till att känna igen. Klicka någonstans i texten på referensprojektets startsida, och skriv sedan i konsolen:

spela är ljudmodulens funktion, och den går att anropa från konsolen. Svaret är rött. Så här står det i Chrome och Edge; Firefox formulerar sig annorlunda:

Uncaught (in promise) NotSupportedError: Failed to load because no supported source was found.

NotSupportedError betyder att filen inte hittades. Ljudet har fel namn, fel versal eller ligger i fel mapp. Kontrollera namnet i data-ljud och LJUDMAPP innan något annat. Modulen tar inte hand om felet, och det är meningen: att få den att klara en saknad fil utan fel i konsolen är en utmaning på nivå A, se avsnitt 7.

4. Koppla in och anpassa en modul

Det här är E-nivån i Projekt 5: ta en modul någon annan skrivit, koppla in den och ändra det som får ändras. Tre frågor bär avsnittet. Var ska script stå? Hur hittar sidan filen? Vilka rader får jag röra?

Det mesta som går fel när en modul kopplas in är inte koden, utan kopplingen. En sida där skript/ljud.js är felstavat till skript/ljd.js byter färger men är tyst. Konsolen har en röd rad om en fil som inte gick att hämta, och ingenting annat klagar.

Syns raden i konsolen på varje sida är sökvägen och defer rätt, innan du skrivit något som kan gå fel.

Sökvägar

Två sökvägar, och båda räknas från sidan:

  • src="skript/ljud.js" räknas från HTML-filen, som href="stil.css" och bildernas src.
  • LJUDMAPP i ljudmodulen räknas också från sidan, inte från skriptfilen. Kommentaren säger det: var ljudfilerna ligger, räknat från sidan. Skriptet ligger i skript/, men ljuden hittas i ljud/ bredvid index.html.

Tre fel som kommer:

  • Snedstreck först. /skript/ljud.js betyder roten, inte mappen bredvid. Det fungerar ibland lokalt och aldrig på Pages. Skriv utan snedstreck först.
  • Omvända snedstreck. skript\ljud.js är Windows sätt att skriva. Webben använder /.
  • Versaler. Skript/ och skript/ är samma mapp i Windows men inte på Pages. Gemener överallt, som i guiden till område 2, avsnitt 10.

Steg 4. Läs vad modulen gör. Hela filen, skript/morkt-lage.js:

// Mörkt läge. Knappen växlar mellan ljust och mörkt och minns valet till nästa besök.
// Utan JavaScript följer sajten systemets inställning, med CSS. Knappen har hidden i
// HTML:en och visas först här, eftersom den inte gör något utan skriptet.

const knapp = document.querySelector(".lage-knapp");
const rot = document.documentElement;

// Är sidan mörk just nu? Ett eget val går före systemets inställning.
function arMork() {
  if (rot.classList.contains("morkt")) {
    return true;
  }
  if (rot.classList.contains("ljust")) {
    return false;
  }
  return matchMedia("(prefers-color-scheme: dark)").matches;
}

// Sätter läget och sparar valet. localStorage kan vara avstängt och kastar då ett
// fel. try gör att sidan fungerar ändå, fast utan minne.
function sattLage(lage) {
  rot.classList.remove("morkt", "ljust");
  rot.classList.add(lage);
  knapp.setAttribute("aria-pressed", lage === "morkt");
  try {
    localStorage.setItem("lage", lage);
  } catch (fel) {
    // Inget minne. Läget gäller tills sidan laddas om.
  }
}

// Ett sparat val från förra besöket
try {
  const sparat = localStorage.getItem("lage");
  if (sparat) {
    sattLage(sparat);
  }
} catch (fel) {
  // Inget sparat val. Systemets inställning gäller.
}

knapp.hidden = false;
knapp.setAttribute("aria-pressed", arMork());

knapp.addEventListener("click", function () {
  if (arMork()) {
    sattLage("ljust");
  } else {
    sattLage("morkt");
  }
});

  rot.classList.add(lage);

  • remove tar bort båda klasserna, add sätter den som valdes. Aldrig båda samtidigt.
  • lage === "morkt" jämför. Tre likhetstecken betyder är lika med, och svaret är true eller false. Det är det ett enkelt = inte är.
  • aria-pressed säger till skärmläsaren att knappen är nedtryckt eller inte. Knappens text är densamma i båda lägena; det är aria-pressed och utseendet som visar läget. I stil.css står utseendet under .lage-knapp[aria-pressed="true"].

  • try betyder försök. Går det fel, till exempel för att lagringen är avstängd, körs det som står i catch i stället, och sidan fungerar ändå.

Varje lager ska fungera utan lagret ovanför. HTML:en ensam är en läsbar sida med länkar och ett formulär. CSS:en gör den bra att använda. JavaScript lägger till ljud och tillstånd. På engelska heter tanken progressive enhancement: basen först, sedan förbättringar som får saknas.

Reglerna du redan följer finns av det skälet. Inget onclick i HTML:en, för då blir beteendet en del av strukturen. Rörelsen i CSS och inte med style, för då ligger utseendet i beteendet. Varje regel håller isär två lager.

Ett skript kan saknas av fler skäl än att någon stängt av det: nätet tappar filen, ett tillägg i webbläsaren blockerar den, eller ett fel på en rad stoppar resten av skriptet. För sajten är det samma sak.

Vad som håller i referensprojektet

Stäng av JavaScript och gå igenom referensprojektet. Rubrikerna, texten, bilderna och menyn är kvar, och alla länkar fungerar. Det enda som saknas på startsidan är lägesknappen.

Lägesknappen. Den står i HTML:en med hidden. Utan skriptet tas hidden aldrig bort, och knappen syns inte. Kommentaren överst i morkt-lage.js säger varför: knappen gör ingenting utan skriptet. En knapp som inte gör något när man trycker är sämre än ingen knapp, för den som trycker tror att sajten är trasig.

hidden fungerar för att webbläsaren döljer elementet med display: none. En egen regel som sätter display på knappen vinner över det:

/* Så här ska det inte stå: display vinner över hidden,
   och knappen syns också utan JavaScript */
.lage-knapp {
  display: inline-flex;
}

Därför har .lage-knapp i referensprojektets stil.css ingen display-regel, och kommentaren där säger att det är avsiktligt. Kontrollera i Elements-fliken vilken regel som gäller om din knapp syns fast den inte borde.

Det mörka läget. Sätt prefers-color-scheme till dark i Rendering-panelen. Sajten blir mörk, utan skript. Det är media queryn med :root:not(.ljust) från avsnitt 4. Den är CSS och bryr sig inte om JavaScript: utan skript finns ingen klass ljust, och villkoret stämmer alltid. Det som försvinner är valet. Att mörkt läge fungerar utan JavaScript är nivå A i uppgiften, och det är skälet till att paletten står två gånger.

Formuläret. Tryck Skicka rapporten på rapportera.html med tomma fält. Webbläsaren stoppar och säger att fältet ska fyllas i. Det är required i HTML:en, och det fungerar utan en rad JavaScript. Fyll i fälten och tabba ut: ingen grön stapel, eftersom falt.js inte körs. Skicka, och tack.html visas som vanligt. Stapeln var en extra bekräftelse. Kontrollen var aldrig beroende av den.

Ljudet. Inget ljud någonstans. Fyrsajtens enda ljud hör till lägesknappen, och den finns inte nu. Ett ljud får aldrig vara det enda som säger något, det tog Gränssnittsdesign den 1 mars, så ingen information försvinner med det.

Innehåll som bara JavaScript skapar

Nu motsatsen, ett påhittat exempel som inte finns i fyrsajten:

<h2>Öppettider</h2>
<p class="oppettider"></p>
// Så här ska det inte göras: texten finns bara om skriptet körs
document.querySelector(".oppettider").textContent = "Öppet alla dagar 10–16.";

Med JavaScript ser sidan rätt ut. Utan är stycket tomt, och rubriken står över ingenting. Samma sak för sökmotorn och för den vars nät tappade skriptfilen. Innehållet hör hemma i HTML:en. JavaScript får ändra det, visa det eller dölja det, men det får inte vara det enda stället där det finns.

Fler mönster som går sönder på samma sätt:

  • En meny som är dold med CSS och bara öppnas med JavaScript. Utan skript finns ingen meny. Det var därför menyn i område 5 fick radbryta i stället.
  • En länk med href="#" och en lyssnare. Utan skript leder den ingenstans. En länk ska ha en riktig adress.
  • En knapp som bara fungerar med skriptet, men som syns utan. Övningsknappen i avsnitt 3 är en sådan. Antingen hidden i HTML:en och en rad i skriptet som tar bort det, eller bort.

Tre tekniska saker

  • Webbläsaren spelar inte ljud förrän användaren gjort något på sidan. Ett ljud när sidan laddas, eller när musen bara passerar, stoppas och ger felet NotAllowedError i konsolen. Hela meddelandet står under listan.

En egen modul styrd med attribut

En modul som fungerar på element den inte byggdes för. Förebilden är ljudmodulen, och det som gör den till en modul är det här:

  • Den styrs från HTML:en. Den som använder den sätter ett attribut och öppnar aldrig filen. Ljudmodulen läser data-ljud och data-ljud-nar med dataset.
  • Den hittar sina element själv, med en attributselektor i querySelectorAll och en loop.
  • Den vet ingenting om sajten. Inga klasser, texter eller sidnamn från just din sajt står i filen.
  • Inställningarna står överst, som versaler, och kommentaren överst säger hur den används och vad som får ändras.
  • Den tål att inget matchar. Kopplas den in på en sida utan element går loopen noll varv, och ingenting händer.

Pröva den på en kamrats sajt. Där ser du om den verkligen inte vet något om din. Skriv i dokumentation.md hur den används, så att någon annan kan koppla in den utan att fråga dig.

Tangentbord och skärmläsare

Alla mikrointeraktioner ska gå att utlösa med tangentbordet, och återkopplingen ska nå också den som använder skärmläsare.

  • Tangentbordet. Lyssnar du på en button eller en a är det mesta redan klart, se avsnitt 3. Lägg undan musen och gör varje handling i överlämningen med Tab, Enter och mellanslag.
  • Ett läge, som på och av, når skärmläsaren med aria-pressed, som lägesknappen.
  • Ett meddelande som dyker upp, till exempel en bekräftelse, når skärmläsaren med aria-live. Ett element med aria-live="polite" läses upp när dess text ändras, så fort skärmläsaren är klar med det den håller på med.

När ljudfilen saknas

Du ska kunna visa vad som händer när en ljudfil saknas, och koden ska klara det utan fel i konsolen. Felet känner du igen från avsnitt 3: Uncaught (in promise) NotSupportedError.

Två ord i felet är ledtråden. play() spelar inte bara ljudet, den ger tillbaka ett löfte, engelska promise: ett besked som kommer senare om uppspelningen lyckades eller inte. Uncaught (in promise) betyder att löftet misslyckades och att ingen kod tog hand om det. MDN, webbens referensverk, beskriver vad play() ger tillbaka och vad som händer när den misslyckas:

https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play

Läs sidan, pröva i konsolen med spela("finns-inte"), och skriv i dokumentation.md vad du ändrade i modulen och varför. En ändring i loopen eller i funktionen betyder att modulen är din att felsöka.

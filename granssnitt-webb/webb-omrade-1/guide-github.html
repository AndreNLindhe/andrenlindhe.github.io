Kom igång med GitHub och Codespaces

Din uppslagsbok för allt som har med inlämningar att göra. Slå upp här när något krånglar i stället för att gissa. Guiden fungerar utan att du varit på lektionen.

Vad du kan efter guiden
  • Acceptera en uppgift i GitHub Classroom och hitta ditt eget repo
  • Öppna, stänga och återuppta ett Codespace utan att tappa arbete
  • Spara ditt arbete så att läraren faktiskt ser det
  • Publicera din sajt på en riktig adress
  • Läsa av vad som gick fel när något inte syns

1. Orden du behöver

OrdVad det betyder
Repo (repository)En mapp som kommer ihåg allt du gjort med den. Ditt projekt
CommitEn sparpunkt. Du beskriver vad du ändrat och varför
Sync (push)Skickar dina sparpunkter till github.com så att de syns för andra
CodespaceEn färdig utvecklingsmiljö som körs i webbläsaren
GitHub PagesGratis publicering av ditt repo som en riktig webbplats
mainNamnet på huvudgrenen i ditt repo. Det är den som publiceras

Det viktigaste att förstå direkt: commit och sync är två olika saker. Du kan committa hur mycket du vill utan att någon annan ser det. Först när du synkar hamnar arbetet på github.com.

2. Acceptera en uppgift

Varje uppgift börjar med en länk från läraren.

  1. Klicka på länken.
  2. Logga in på GitHub. Använd samma konto varje gång.
  3. Välj ditt namn i listan första gången du accepterar en uppgift i kursen.
  4. Klicka Accept this assignment.
  5. Vänta några sekunder och ladda om sidan. Du får en länk till ditt eget repo.

Repot heter något i stil med omrade-1-sa-fungerar-webben-dittanvandarnamn. Det är ditt, ingen annan elev ser det. Läraren ser det.

Har du inget GitHub-konto? Skapa ett på github.com innan du klickar på länken. Välj ett användarnamn du kan tänka dig att visa upp – det syns i adressen till allt du publicerar.

Prova själv

Gå till github.com och leta upp ditt repo under Your repositories. Ligger det inte där har du accepterat med fel konto. Säg till läraren, det går att rätta.

3. Öppna ditt Codespace

Ett Codespace är en dator i molnet med allt förinstallerat. Du behöver inte installera något själv.

  1. Gå till ditt repo på github.com.
  2. Klicka på den gröna knappen Code.
  3. Välj fliken Codespaces.
  4. Klicka Create codespace on main.

Första gången tar det en till två minuter. Klicka inte igen om det känns långsamt – då startar du ett andra codespace och blandar ihop var filerna ligger.

När det öppnats ser du en filutforskare till vänster, en redigerare i mitten och en terminal längst ner. Det är samma program som Visual Studio Code, fast i webbläsaren.

Förhandsvisa din sida

Öppna index.html, högerklicka i filen och välj Open with Live Preview, eller använd tillägget som redan finns installerat. Sidan visas bredvid koden och uppdateras när du sparar.

Förhandsvisningen är inte samma sak som den publicerade sidan. Sökvägar kan fungera i förhandsvisningen men gå sönder på GitHub Pages. Kontrollera alltid den publicerade sidan innan du är klar.

4. Spara arbete: commit och sync

Det här är det enda i guiden du måste kunna utantill.

  1. Klicka på källkontroll i vänstermarginalen – ikonen med tre punkter och streck. Siffran visar hur många filer du ändrat.
  2. Skriv ett meddelande i rutan högst upp. Beskriv vad du gjort, inte att du gjort något: Lade till avsnittet om DNS, inte ändringar.
  3. Klicka Commit.
  4. Klicka Sync Changes (kan heta Push).

Ladda sedan om ditt repo på github.com. Ser du din ändring där är den inlämnad.

Det som inte syns på github.com är inte inlämnat. Läraren tittar på github.com, inte i ditt codespace.

Hur ofta ska du committa?

Varje gång du blir klar med något som fungerar. En bra tumregel är tre till fem commits per lektion. Många små commits är bättre än en stor, av två skäl: du kan gå tillbaka till en punkt där det fungerade, och din commit-historik visar att du arbetat löpande – det ingår i bedömningen av slutprojektet.

Prova själv

Ändra en rad i README.md, committa med ett beskrivande meddelande, synka, och kontrollera att texten syns på github.com. Gör det nu, medan du inte har något att förlora.

5. Publicera med GitHub Pages

  1. Gå till ditt repo på github.com.
  2. Klicka Settings överst.
  3. Välj Pages i vänstermenyn.
  4. Under Source, välj Deploy from a branch.
  5. Välj grenen main och mappen / (root). Klicka Save.
  6. Vänta en till två minuter. Ladda om sidan – adressen visas överst.

Adressen ser ut så här:

https://dittanvandarnamn.github.io/repots-namn/

Publiceringen sker om automatiskt varje gång du synkar. Det tar upp till en minut, så en ändring syns inte direkt.

Krav för att det ska fungera

  • Startsidan måste heta index.html och ligga i repots rot.
  • Sökvägar måste vara relativa: bilder/logga.png, inte /bilder/logga.png och inte C:\Users\....
  • Filnamn måste stämma exakt, inklusive stora och små bokstäver.

Den sista punkten är den vanligaste orsaken till att en bild försvinner vid publicering. Din egen dator bryr sig inte om skillnaden mellan Logga.png och logga.png. Servern gör det.

6. Arbeta över flera pass

Ett codespace stängs ner automatiskt efter en halvtimmes inaktivitet. Ditt arbete är kvar – men bara det du committat är säkert.

Så här återupptar du:

  1. Gå till ditt repo.
  2. Code → Codespaces.
  3. Klicka på det codespace som redan finns i listan. Skapa inte ett nytt.
Rutin som sparar dig mycket besvär

Först på passet: öppna befintligt codespace, kontrollera att du är i rätt repo.
Sista fem minuterna: committa och synka. Alltid, även om du inte är klar.

Codespaces har en månatlig gratiskvot. Stäng ner ditt codespace när du är klar för dagen: Code → Codespaces → de tre punkterna → Stop codespace. Då förbrukar det ingenting.

7. Ta det längre

Det här behöver du inte, men det gör arbetet smidigare.

Läs din historik. På github.com, klicka på commits ovanför fillistan. Du ser varje sparpunkt, vem som gjorde den och exakt vilka rader som ändrades. Klicka på en commit för att se skillnaden rad för rad.

Ångra till en tidigare version. Har du förstört en fil kan du hämta tillbaka den gamla: öppna filen på github.com, klicka History, välj en tidigare version och kopiera innehållet.

Arbeta i terminalen. Allt i källkontrollpanelen går att göra med kommandon:

git status                     # vad har ändrats?
git add .                      # ta med alla ändringar
git commit -m "Lade till DNS-avsnittet"
git push                       # skicka till github.com

Du behöver inte kunna det här i kursen, men i slutprojektet går det fortare.

En .gitignore talar om vilka filer som inte ska följa med. Skräpfiler som .DS_Store och Thumbs.db hör inte hemma i ett repo.

2. Det här ska sitta

  • Du kan välja typ medvetet och säga varför ett fält är int och inte double.
  • Du kan läsa ett kodstycke och säga vad det skriver ut, utan att köra det.
  • Du kan skriva ett villkor som täcker också gränsfallet och det oväntade värdet.
  • Du kan gå igenom en lista med en loop och samla ihop ett svar under vägen.
  • Du kan lyfta ut en uträkning ur markupen och lägga den i en metod.
  • Du kan beskriva något med en egen klass och rendera en lista med objekt som en tabell.
  • Du följer C#:s namngivning: PascalCase på metoder och egenskaper, camelCase på variabler.

3. Fyra sidor, inte en

Övningarna ligger på fyra sidor i ditt projekt, en per tema. Det är inte pyssel – det finns två konkreta skäl.

Sida i ditt projektÖvningarTema
/ovningar/typer1–7Uttryck, typer, utdata
/ovningar/villkor8–14Villkor och logik
/ovningar/loopar15–21Loopar, listor, arrayer
/ovningar/metoder22–28Metoder, klasser, objekt
Ett fel stoppar hela sidan

Kompilerar inte övning 17 går övning 1–16 inte att visa heller – sidan blir tom. Fyra sidor begränsar skadan till ett tema. Får du plötsligt en tom sida: läs det första felet i terminalen, inte det sista.

Prefixa variabelnamnen

Alla @code-block på en sida blir samma klass. Två övningar som båda använder summa ger CS0102: already contains a definition. Döp fälten efter övningens nummer från början – o3Pris, o3MedMoms – så slipper du döpa om tolv variabler i vecka fyra.

4. Kom igång

Du behöver ett projekt att öva i. Skapa ett nytt, eller fortsätt i projektet från område 1 – blanda då inte ihop sidorna.

StegDet du gör
1Skapa ett tomt, publikt repo på github.com som heter ovningsbanken. Inga bockar.
2Skapa projektet: dotnet new blazor -o Ovningsbanken -int None
3Gå in i mappen och kör det: cd Ovningsbanken och dotnet run
4Skapa de fyra sidorna i Components/Pages/, med @page "/ovningar/typer" och så vidare.
5Lägg in de fyra sidorna i menyn, Components/Layout/NavMenu.razor.
6Koppla på GitHub: git init, git add ., git commit -m "Fyra tomma övningssidor", git branch -M main, git remote add origin …, git push -u origin main

Committa efter varje övningspass, inte allt sista kvällen. Fem commits är ett krav i uppgiften just därför.

6. Orden

Orden nedan används från och med nu utan förklaring. Träna tills du kan dem – en av provets fyra frågetyper är förklara.

Ordträning

OrdBetyder
datatypVad ett värde är för sorts sak: text, heltal, decimaltal, sant eller falskt.
variabelEtt namn som håller ett värde.
fältEn variabel som hör till komponenten och lever så länge sidan byggs.
interpolationAtt sätta in värden mitt i en text med $"..." i stället för att limma ihop den med plus.
heltalsdivisionNär båda talen är heltal kastas decimalerna bort. 7 delat med 2 blir 3.
moduloResten vid en division, skrivet %. 142 % 60 är 22.
villkorEn fråga som besvaras med sant eller falskt.
operatorEtt tecken som gör något med värden: +, >=, &&.
loopKod som körs flera gånger.
indexPlatsen i en lista. Den första platsen är 0.
listaEn samling värden i en variabel, List<T>.
metodEtt namngivet kodstycke som tar emot värden och lämnar tillbaka ett svar.
parameterVärdet en metod tar emot, namngivet inuti metoden.
returvärdeDet metoden lämnar tillbaka till den som anropade den.
klassEn beskrivning av vad något är: vilka egenskaper det har.
objektEn sak skapad ur en klass med new.
egenskapEtt namngivet värde som hör till ett objekt. Skrivs i PascalCase.
PascalCaseStor bokstav i varje ord: LangdMinuter. Används på klasser, metoder och egenskaper.
camelCaseLiten bokstav först: antalMinuter. Används på variabler och parametrar.
frågesträngVärdena efter ? i adressen. Läses med [SupplyParameterFromQuery].

Extraövningar

Trettio övningar till för dig som vill träna mer på grunderna: tjugo lätta och tio medel, i samma fyra teman som övningsbanken. De räknas inte in i någon inlämning. De finns för att det som sitter lite löst ska få sitta ordentligt.

Så här använder du sidan

Försök först, titta sedan

Varje övning har en lösning bakom knappen Visa en lösning. Öppna den när du är klar, eller när du suttit fast i tio minuter – inte innan. Den som läser lösningen först lär sig läsa kod. Den som skriver först lär sig skriva den, och det är det provet och projekten kräver.

Fastnar du: läs Ledtråden, och sedan det steg i guiden som övningen bygger på.

  1. Skapa fyra nya sidor i ditt projekt, i Components/Pages/: /extra/typer, /extra/villkor, /extra/loopar och /extra/metoder.
  2. Varje övning får en egen rubrik och ett eget @code-block direkt under. Samma upplägg som i övningsbanken.
  3. Prefixa namnen med övningens nummer: x1Namn, x8Tal, X19Summa(). Utan prefix krockar de med varandra och sidan slutar kompilera.
  4. Kör, och kontrollera mot Klart när. Stämmer det är övningen löst – din lösning behöver inte se ut som den här.

Lätt – gör precis det som visats i guiden. Medel – kombinera två saker, eller tänk på ett gränsfall.

Uttryck och typer · X1–X7

Sidan /extra/typer. Bygger på guidens steg 2–5.

X1. Om dig själv

Lätt · tränar: de fyra grundtyperna

Skapa fyra fält om dig själv: ditt namn (string), din ålder (int), din längd i meter (double) och om du har körkort (bool). Skriv ut vart och ett på en egen rad med en etikett framför, till exempel Ålder: 17 år.

Ledtråd: ett decimaltal skrivs med punkt i koden, 1.68, men visas med komma på sidan.

Klart när: fyra rader syns, och längden visas med komma.

Visa en lösning 
<p>Namn: @x1Namn</p>
<p>Ålder: @x1Alder år</p>
<p>Längd: @x1Langd meter</p>
<p>Har körkort: @x1Korkort</p>

@code {
    private string x1Namn = "Ada";
    private int x1Alder = 17;
    private double x1Langd = 1.68;
    private bool x1Korkort = false;
}

Varför: @x1Korkort skrivs ut som False. Det är så C# visar ett bool – X26 visar hur du får Ja och Nej i stället.

X2. Plus, minus, gånger

Lätt · tränar: räknesätt och @( ) i markupen

Två fält håller talen 17 och 5. Visa summan, differensen och produkten, en per rad: 17 + 5 = 22.

Ledtråd: en uträkning i markupen behöver parentes: @(x2A + x2B). Utan parentes skrivs @x2A ut och sedan texten + x2B.

Klart när: sidan visar 22, 12 och 85.

Visa en lösning 
<p>@x2A + @x2B = @(x2A + x2B)</p>
<p>@x2A - @x2B = @(x2A - x2B)</p>
<p>@x2A * @x2B = @(x2A * x2B)</p>

@code {
    private int x2A = 17;
    private int x2B = 5;
}

Varför: på varje rad står det första + utanför parentesen och är bara text. Inuti @( ) är det C# och räknas ut.

X3. Rektangeln

Lätt · tränar: double och en formel

En rektangel är 4,5 meter bred och 3 meter hög. Räkna ut arean (bredd × höjd) och omkretsen (två bredder plus två höjder).

Ledtråd: båda måtten ska vara double, eftersom bredden har decimaler.

Klart när: arean är 13,5 och omkretsen 15.

Visa en lösning 
<p>Rektangeln är @x3Bredd gånger @x3Hojd meter.</p>
<p>Arean är @x3Area kvadratmeter och omkretsen @x3Omkrets meter.</p>

@code {
    private double x3Bredd = 4.5;
    private double x3Hojd = 3;
    private double x3Area => x3Bredd * x3Hojd;
    private double x3Omkrets => 2 * x3Bredd + 2 * x3Hojd;
}

Varför: => gör att arean räknas ut varje gång den visas. Ändrar du bredden följer arean med av sig själv.

X4. Biljetterna

Lätt · tränar: stränginterpolation

Tre biljetter kostar 120 kronor styck. Skriv ut meningen 3 biljetter à 120 kr kostar 360 kr. – där alla tre talen kommer ur fält, och totalen räknas ut.

Ledtråd: $"{x4Antal} biljetter …". Dollartecknet före citattecknet gör att klammerparenteserna byts mot värden.

Klart när: meningen stämmer, och ändrar du antalet till 4 blir totalen 480 utan att du rör något annat.

Visa en lösning 
<p>@x4Rad</p>

@code {
    private int x4Antal = 3;
    private int x4Pris = 120;
    private int x4Totalt => x4Antal * x4Pris;
    private string x4Rad => $"{x4Antal} biljetter à {x4Pris} kr kostar {x4Totalt} kr.";
}

Varför: totalen är ett eget fält som räknas ur de andra två. Skriver du 360 för hand stämmer det bara tills någon ändrar antalet.

X5. Rabatten

Lätt · tränar: procent och två decimaler

En jacka kostar 499 kronor och har 20 procents rabatt. Visa ordinarie pris, rabatten i kronor och vad du betalar – alla med två decimaler.

Ledtråd: 20 procent är 0.20. Två decimaler får du med .ToString("0.00").

Klart när: sidan visar 499,00, 99,80 och 399,20.

Visa en lösning 
<p>Ordinarie pris: @x5Pris.ToString("0.00") kr</p>
<p>Rabatt: @x5Rabatt.ToString("0.00") kr</p>
<p>Att betala: @x5NyttPris.ToString("0.00") kr</p>

@code {
    private double x5Pris = 499;
    private double x5Rabatt => x5Pris * 0.20;
    private double x5NyttPris => x5Pris - x5Rabatt;
}

Varför: utan "0.00" skrivs rabatten ut som 99,8. Det är samma tal – formatet ändrar bara hur det visas.

X6. Medelpoängen

Medel · tränar: heltalsdivision och (double)

Tre prov gav 14, 17 och 12 poäng, lagrade som int. Visa medelpoängen med en decimal.

Klart när: sidan visar 14,3. Visar den 14 har decimalerna kastats bort – läs steg 4 igen.

Visa en lösning 
<p>Poängen: @x6Prov1, @x6Prov2 och @x6Prov3</p>
<p>Medelpoäng: @x6Medel.ToString("0.0")</p>

@code {
    private int x6Prov1 = 14;
    private int x6Prov2 = 17;
    private int x6Prov3 = 12;
    private double x6Medel => (double)(x6Prov1 + x6Prov2 + x6Prov3) / 3;
}

Varför: 43 / 3 är 14 när båda talen är int. (double) gör om summan till decimaltal före divisionen, och då blir svaret 14,333…

Vanlig felväg: (double)(43 / 3). Där sker divisionen först, som heltal, och 14 blir 14,0.

X7. Sekunderna

Medel · tränar: / och % i två steg

Skriv en metod som tar emot ett antal sekunder och lämnar tillbaka samma tid som timmar, minuter och sekunder.

Klart när: 3725 ger 1 h 2 min 5 s, 59 ger 0 h 0 min 59 s och 3600 ger 1 h 0 min 0 s.

Visa en lösning 
<p>3725 sekunder: @X7Tid(3725)</p>
<p>59 sekunder: @X7Tid(59)</p>
<p>3600 sekunder: @X7Tid(3600)</p>

@code {
    private string X7Tid(int sekunder)
    {
        int timmar = sekunder / 3600;
        int rest = sekunder % 3600;
        int minuter = rest / 60;
        int sek = rest % 60;
        return $"{timmar} h {minuter} min {sek} s";
    }
}

Varför: en timme är 3600 sekunder. / 3600 ger hela timmar och % 3600 det som blir över. Samma sak en gång till med 60 delar upp resten i minuter och sekunder.

Villkor och logik · X8–X15

Sidan /extra/villkor. Bygger på guidens steg 6–9.

X8. Plus eller minus

Lätt · tränar: if, else if, else

Ett fält håller ett heltal. Skriv ut om talet är positivt, negativt eller noll.

Ledtråd: tre utfall betyder if, else if och else. Lägg logiken i en metod som lämnar tillbaka ordet.

Klart när: 5, -3 och 0 ger tre olika svar.

Visa en lösning 
<p>@x8Tal är @X8Tecken(x8Tal).</p>

@code {
    private int x8Tal = -3;

    private string X8Tecken(int tal)
    {
        if (tal > 0)
        {
            return "positivt";
        }
        else if (tal < 0)
        {
            return "negativt";
        }
        else
        {
            return "noll";
        }
    }
}

Varför: else behöver inget villkor. Är talet varken större eller mindre än noll finns bara ett alternativ kvar.

X9. Jämnt eller udda

Lätt · tränar: modulo i ett villkor

Skriv en metod som avgör om ett tal är jämnt eller udda. Pröva den på 4, 7 och 0.

Ledtråd: ett tal är jämnt om resten blir noll när du delar med två: tal % 2 == 0.

Klart när: 4 och 0 ger jämnt, 7 ger udda.

Visa en lösning 
<p>4 är @X9JamntUdda(4).</p>
<p>7 är @X9JamntUdda(7).</p>
<p>0 är @X9JamntUdda(0).</p>

@code {
    private string X9JamntUdda(int tal)
    {
        if (tal % 2 == 0)
        {
            return "jämnt";
        }
        return "udda";
    }
}

Varför: return avslutar metoden direkt. Därför behövs ingen else – raden return "udda" nås bara om villkoret var falskt.

X10. Godkänt?

Lätt · tränar: ? : och gränsvärden

Ett prov kräver 60 poäng för godkänt. Visa godkänt eller inte godkänt med villkor ? "ja" : "nej", direkt i markupen.

Klart när: 59 ger inte godkänt och 60 ger godkänt.

Visa en lösning 
<p>@x10Poang poäng: @(x10Poang >= 60 ? "godkänt" : "inte godkänt")</p>

@code {
    private int x10Poang = 60;
}

Varför: >=, inte >. Den som har exakt 60 ska klara sig. Pröva alltid gränsvärdet självt – det är där felen gömmer sig.

X11. Det största av två

Lätt · tränar: jämförelser med tre utfall

Två fält håller var sitt heltal. Skriv ut vilket som är störst – eller att de är lika.

Klart när: 3 och 8 ger 8 är störst, 9 och 2 ger 9 är störst, och 5 och 5 ger talen är lika.

Visa en lösning 
<p>@x11A och @x11B: @X11Storst(x11A, x11B)</p>

@code {
    private int x11A = 3;
    private int x11B = 8;

    private string X11Storst(int a, int b)
    {
        if (a > b)
        {
            return $"{a} är störst";
        }
        else if (b > a)
        {
            return $"{b} är störst";
        }
        return "talen är lika";
    }
}

Varför: det lätta är att glömma det tredje fallet. Med bara if (a > b) och else påstår koden att 5 är större än 5.

X12. Inloggad eller inte

Lätt · tränar: @if som väljer HTML

Ett bool säger om besökaren är inloggad. Är hen det: visa en fet välkomsttext. Annars: visa en länk med texten Logga in.

Ledtråd: steg 7. @if i markupen, med HTML inuti klammerparenteserna.

Klart när: du ändrar fältet till false, laddar om, och sidkällan innehåller länken men inte välkomsttexten.

Visa en lösning 
@if (x12Inloggad)
{
    <p><strong>Välkommen tillbaka!</strong></p>
}
else
{
    <p><a href="/">Logga in</a> för att se dina filmer.</p>
}

@code {
    private bool x12Inloggad = true;
}

Varför: grenen som inte tas skickas aldrig till webbläsaren. Den är inte dold – den finns inte. Riktig inloggning kommer i område 7.

X13. Biljettpriset

Medel · tränar: en kedja av villkor och gränsfall

Skriv en metod som tar emot en ålder och lämnar tillbaka biljettpriset:

  • under 7 år: gratis
  • 7–17 år: 60 kr
  • 18–64 år: 120 kr
  • 65 år och äldre: 80 kr

Klart när: 6, 7, 17, 18, 64 och 65 ger gratis, 60, 60, 120, 120 och 80. Det är gränserna som avslöjar felen, så pröva alla sex.

Visa en lösning 
<ul>
    <li>6 år: @X13Pris(6)</li>
    <li>7 år: @X13Pris(7)</li>
    <li>17 år: @X13Pris(17)</li>
    <li>18 år: @X13Pris(18)</li>
    <li>64 år: @X13Pris(64)</li>
    <li>65 år: @X13Pris(65)</li>
</ul>

@code {
    private string X13Pris(int alder)
    {
        if (alder < 7)
        {
            return "gratis";
        }
        else if (alder < 18)
        {
            return "60 kr";
        }
        else if (alder < 65)
        {
            return "120 kr";
        }
        return "80 kr";
    }
}

Varför: villkoren prövas uppifrån och ned, och det första som stämmer vinner. Därför räcker alder < 18 på andra raden – den som är under 7 har redan fått sitt svar.

X14. Storleken i adressen

Medel · tränar: [SupplyParameterFromQuery] och switch

Läs en storlek ur adressen: ?storlek=s, m eller l. Visa priset med en switch: 199, 249 eller 299 kr. Saknas storleken ska sidan be besökaren välja en. En okänd storlek ska ge ett eget meddelande.

Ledtråd: egenskapen är public string? Storlek { get; set; }. Frågetecknet betyder att den får vara tom – null – och det är den när adressen saknar värdet.

Klart när: /extra/villkor, ?storlek=m och ?storlek=xl ger tre olika svar, och sidan inte kraschar på något.

Visa en lösning 
<p>@X14Pris(Storlek)</p>

@code {
    // ?storlek=m i adressen. Saknas värdet blir Storlek null.
    [SupplyParameterFromQuery]
    public string? Storlek { get; set; }

    private string X14Pris(string? storlek) => storlek switch
    {
        "s" => "Liten: 199 kr",
        "m" => "Mellan: 249 kr",
        "l" => "Stor: 299 kr",
        null => "Välj en storlek: lägg till ?storlek=m i adressen.",
        _ => $"Storleken {storlek} finns inte."
    };
}

Varför: en switch kan jämföra text lika gärna som tal. null fångar adressen utan värde, _ fångar allt annat. Egenskapen heter Storlek utan prefix eftersom namnet är det som står i adressen.

X15. Rabattkoden

Medel · tränar: && och || i samma villkor

En butik ger rabatt till medlemmar som handlar för minst 500 kr – och till alla som handlar för minst 1000 kr, medlem eller inte. Skriv en metod som tar emot bool medlem och int belopp och svarar rabatt eller ingen rabatt.

Klart när: medlem för 600 får rabatt, icke-medlem för 600 får inte, icke-medlem för 1200 får rabatt, och medlem för 300 får inte.

Visa en lösning 
<ul>
    <li>Medlem, 600 kr: @X15Rabatt(true, 600)</li>
    <li>Inte medlem, 600 kr: @X15Rabatt(false, 600)</li>
    <li>Inte medlem, 1200 kr: @X15Rabatt(false, 1200)</li>
    <li>Medlem, 300 kr: @X15Rabatt(true, 300)</li>
</ul>

@code {
    private string X15Rabatt(bool medlem, int belopp)
    {
        if ((medlem && belopp >= 500) || belopp >= 1000)
        {
            return "rabatt";
        }
        return "ingen rabatt";
    }
}

Varför: parentesen runt medlem && belopp >= 500 gör villkoret läsbart: (medlem som handlar för 500) eller (vem som helst som handlar för 1000).

Loopar och listor · X16–X23

Sidan /extra/loopar. Bygger på guidens steg 10–13.

X16. Nedräkningen

Lätt · tränar: for baklänges

Skriv ut talen 10 ned till 1, ett per rad, och sist texten Lyft!

Ledtråd: börja på 10, fortsätt så länge i >= 1, och minska med i--.

Klart när: första raden är 10, sista talet är 1, och Lyft! står en gång – inte tio.

Visa en lösning 
@for (int i = 10; i >= 1; i--)
{
    <p>@i</p>
}
<p>Lyft!</p>

Varför: Lyft! står efter loopens avslutande klammerparentes. Inuti hade den skrivits ut varje varv.

X17. De jämna talen

Lätt · tränar: for med ett annat steg än ett

Visa de jämna talen från 2 till 20 som en punktlista.

Ledtråd: den sista delen av for behöver inte vara i++. Den kan vara i = i + 2.

Klart när: listan har tio punkter, från 2 till 20.

Visa en lösning 
<ul>
    @for (int i = 2; i <= 20; i = i + 2)
    {
        <li>@i</li>
    }
</ul>

Varför: <ul> står utanför loopen och <li> inuti. En lista, tio punkter.

X18. Inköpslistan

Lätt · tränar: List<string>, foreach och index

Skapa en inköpslista med fem saker. Visa dem som en punktlista, och under den: hur många saker det är, vilken som står först och vilken som står sist.

Ledtråd: den första ligger på plats [0]. Den sista ligger på plats Count - 1.

Klart när: lägger du till en sjätte sak sist i listan visar sidan sex saker och den nya som sist – utan att du ändrat något annat.

Visa en lösning 
<ul>
    @foreach (string vara in x18Lista)
    {
        <li>@vara</li>
    }
</ul>
<p>@x18Lista.Count saker. Först: @x18Lista[0]. Sist: @x18Lista[x18Lista.Count - 1].</p>

@code {
    private List<string> x18Lista = new() { "Mjölk", "Bröd", "Ost", "Äpplen", "Kaffe" };
}

Varför: fem saker ligger på plats 0 till 4. x18Lista[5] finns inte och kraschar sidan. Count - 1 pekar alltid rätt, hur lång listan än blir.

X19. Summan av 1 till 100

Lätt · tränar: att samla ihop ett värde i en loop

Räkna ut summan av alla heltal från 1 till 100 med en for-loop, i en metod.

Ledtråd: steg 11. En variabel summa = 0 före loopen, och summa = summa + i inuti.

Klart när: svaret är 5050.

Visa en lösning 
<p>Summan av 1 till 100 är @X19Summa().</p>

@code {
    private int X19Summa()
    {
        int summa = 0;
        for (int i = 1; i <= 100; i++)
        {
            summa = summa + i;
        }
        return summa;
    }
}

Varför: summa skapas utanför loopen. Inuti hade den nollställts varje varv, och svaret hade blivit 100.

X20. Spargrisen

Lätt · tränar: while

Du sparar 150 kronor i veckan. Hur många veckor tar det innan du har minst 1000 kronor? Lös det med en while-loop som räknar veckorna.

Ledtråd: steg 12. Loopen fortsätter så länge sparat < 1000. Varje varv: lägg till 150 och räkna upp veckorna.

Klart när: sidan säger 7 veckor och 1050 kronor.

Visa en lösning 
<p>@X20Spara()</p>

@code {
    private string X20Spara()
    {
        int sparat = 0;
        int veckor = 0;

        while (sparat < 1000)
        {
            sparat = sparat + 150;
            veckor++;
        }

        return $"Efter {veckor} veckor finns {sparat} kr i spargrisen.";
    }
}

Varför: while passar när du inte vet hur många varv det blir. Glömmer du att öka sparat blir villkoret aldrig falskt och sidan svarar aldrig – avbryt med Ctrl+C.

X21. Minusgraderna

Medel · tränar: tabell ur en lista, villkor i en loop

En List<int> håller en veckas temperaturer: 3, -2, -5, 0, 1, -1 och 4. Visa dem i en tabell med dagens nummer (1–7), graderna, och en kolumn som säger Ja om det var minusgrader. Visa under tabellen hur många dagar som hade minusgrader.

Klart när: tabellen har sju rader och börjar på dag 1, och räknaren säger 3. Noll är inte minusgrader.

Visa en lösning 
<table>
    <tr><th>Dag</th><th>Grader</th><th>Minus?</th></tr>
    @for (int i = 0; i < x21Grader.Count; i++)
    {
        <tr>
            <td>@(i + 1)</td>
            <td>@x21Grader[i]</td>
            <td>@(x21Grader[i] < 0 ? "Ja" : "Nej")</td>
        </tr>
    }
</table>
<p>Dagar med minusgrader: @X21AntalMinus()</p>

@code {
    private List<int> x21Grader = new() { 3, -2, -5, 0, 1, -1, 4 };

    private int X21AntalMinus()
    {
        int antal = 0;
        foreach (int grad in x21Grader)
        {
            if (grad < 0)
            {
                antal++;
            }
        }
        return antal;
    }
}

Varför: tabellen använder for eftersom dagens nummer ska synas – @(i + 1). Räknaren använder foreach eftersom den bara behöver värdena.

X22. Kvittot

Medel · tränar: List<double> och summa med decimaler

En List<double> håller fyra priser: 24,90, 12,50, 89 och 5,95. Visa dem som en numrerad lista med två decimaler, och summan under, också med två decimaler. Räkna ut summan själv – utan Sum().

Klart när: priset 89 visas som 89,00, och summan är 132,35.

Visa en lösning 
<ol>
    @foreach (double pris in x22Priser)
    {
        <li>@pris.ToString("0.00") kr</li>
    }
</ol>
<p><strong>Att betala: @X22Summa().ToString("0.00") kr</strong></p>

@code {
    private List<double> x22Priser = new() { 24.90, 12.50, 89, 5.95 };

    private double X22Summa()
    {
        double summa = 0;
        foreach (double pris in x22Priser)
        {
            summa = summa + pris;
        }
        return summa;
    }
}

Varför: summa är double, inte int. Med int kompilerar det inte ens – C# vägrar lägga ett decimaltal i ett heltal utan att du ber om det.

X23. Trappan

Medel · tränar: en loop inuti en loop

Rita en trappa av stjärnor: fem rader, där rad 1 har en stjärna, rad 2 två stjärnor, och så vidare.

Klart när: sista raden har fem stjärnor. Ändrar du 5 till 8 på ett ställe blir trappan åtta rader hög.

Visa en lösning 
@for (int rad = 1; rad <= 5; rad++)
{
    string stjarnor = "";
    for (int i = 1; i <= rad; i++)
    {
        stjarnor = stjarnor + "*";
    }
    <p>@stjarnor</p>
}

Varför: den yttre loopen gör raderna. Den inre bygger upp en text med lika många stjärnor som radens nummer. stjarnor skapas inuti den yttre loopen, så att varje rad börjar tom.

Metoder och klasser · X24–X30

Sidan /extra/metoder. Bygger på guidens steg 14–16.

X24. Dubbla

Lätt · tränar: en metod med parameter och returvärde

Skriv en metod som tar emot ett heltal och lämnar tillbaka det dubbla. Anropa den med 3, 50 och -4.

Ledtråd: private int X24Dubbla(int tal). Det första int är vad metoden lämnar tillbaka, det inom parentesen är vad den tar emot.

Klart när: sidan visar 6, 100 och -8.

Visa en lösning 
<p>@X24Dubbla(3) · @X24Dubbla(50) · @X24Dubbla(-4)</p>

@code {
    private int X24Dubbla(int tal) => tal * 2;
}

Varför: => fungerar när metoden är ett enda uttryck. Behövs flera rader skriver du { } och return.

Skriv en metod som tar emot ett namn och lämnar tillbaka Hej, Ada! med namnet insatt. Anropa den med två olika namn.

Klart när: två olika hälsningar syns, och metoden heter något som börjar med versal.

Visa en lösning 
<p>@X25Halsa("Ada")</p>
<p>@X25Halsa("Linus")</p>

@code {
    private string X25Halsa(string namn) => $"Hej, {namn}!";

Varför: metoden heter X25Halsa i PascalCase, parametern namn i camelCase. Det är C#:s namngivning, och den bedöms.

X26. Ja eller nej

Lätt · tränar: en metod som lämnar tillbaka ett bool

Skriv en metod X26ArJamnt som tar emot ett heltal och lämnar tillbaka true om det är jämnt. Visa svaret för 8 och 13 som Ja eller Nej.

Ledtråd: metoden kan vara en enda rad: => tal % 2 == 0. Jämförelsen är redan ett bool.

    private bool X26ArJamnt(int tal) => tal % 2 == 0;

Varför: metoden svarar på en fråga, markupen bestämmer hur svaret visas. Två olika uppgifter, på två olika ställen.

X27. Med moms

Lätt · tränar: en metod med double

Skriv en metod som tar emot ett pris utan moms och lämnar tillbaka priset med 25 procents moms. Visa svaret med två decimaler för 200 och 39,60.

Ledtråd: pris plus 25 procent är samma sak som pris gånger 1.25.

Klart när: 200 blir 250,00 och 39,60 blir 49,50.

<p>200 kr blir @X27MedMoms(200).ToString("0.00") kr med moms.</p>
<p>39,60 kr blir @X27MedMoms(39.60).ToString("0.00") kr med moms.</p>

På sidan:

Skapa en lista med fyra böcker och visa dem i en tabell: en rad per bok, en kolumn per egenskap. Skriv en metod som räknar ut hur många sidor böckerna har tillsammans, och visa svaret under tabellen.

Klart när: tabellen har fyra rader, summan stämmer om du räknar efter, och en femte bok i listan syns i tabellen och i summan utan att du rör något annat.

Visa en lösning

    <tr><th>Titel</th><th>Författare</th><th>Sidor</th></tr>
    @foreach (Bok bok in x29Bocker)

    }
</table>

@code {
    private List<Bok> x29Bocker = new()
    {
        new Bok { Titel = "Mio, min Mio", Forfattare = "Astrid Lindgren", Sidor = 180 },
        new Bok { Titel = "Hobbiten", Forfattare = "J.R.R. Tolkien", Sidor = 310 },

X30. Tunn eller tjock

Medel · tränar: en metod med villkor, använd i en tabell

Skriv en metod som tar emot ett antal sidor och lämnar tillbaka tunn (under 200), mellan (200–399) eller tjock (400 och fler). Visa böckerna i en tabell med en kolumn för storleken, och under tabellen hur många som är tjocka.

Klart när: en bok på exakt 200 sidor är mellan, inte tunn, och räknaren stämmer med tabellen.

Visa en lösning 
@using Ovningsbanken.Models

<table>
    <tr><th>Titel</th><th>Sidor</th><th>Storlek</th></tr>
    @foreach (Bok bok in x30Bocker)
    {
        <tr><td>@bok.Titel</td><td>@bok.Sidor</td><td>@X30Storlek(bok.Sidor)</td></tr>
    }
</table>
<p>Tjocka böcker: @X30AntalTjocka()</p>

@code {
    private List<Bok> x30Bocker = new()
    {
        new Bok { Titel = "Mio, min Mio", Forfattare = "Astrid Lindgren", Sidor = 180 },
        new Bok { Titel = "Hobbiten", Forfattare = "J.R.R. Tolkien", Sidor = 310 },
        new Bok { Titel = "Doktor Glas", Forfattare = "Hjalmar Söderberg", Sidor = 160 },
        new Bok { Titel = "Utvandrarna", Forfattare = "Vilhelm Moberg", Sidor = 520 },
        new Bok { Titel = "Pippi Långstrump", Forfattare = "Astrid Lindgren", Sidor = 200 }
    };

    private string X30Storlek(int sidor)
    {
        if (sidor < 200)
        {
            return "tunn";
        }
        else if (sidor < 400)
        {
            return "mellan";
        }
        return "tjock";
    }

    private int X30AntalTjocka()
    {
        int antal = 0;
        foreach (Bok bok in x30Bocker)
        {
            if (X30Storlek(bok.Sidor) == "tjock")
            {
                antal++;
            }
        }
        return antal;
    }
}

Varför: räknaren anropar samma metod som tabellen. Ändrar du gränsen för tjock på ett ställe följer båda med – det är vad en metod är till för.

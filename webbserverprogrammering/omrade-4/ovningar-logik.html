57. Konstruktorinjektion

Lätt · tränar: att ta emot ett beroende i konstruktorn

Ge tjänsten från övning 54 en konstruktor som tar emot en ILogger<Ovning54> och sparar den i ett readonly-fält. Skriv en loggrad i HamtaNamnAsync.

Du registrerar inte loggaren – ramverket har den.

Klart när: raden syns i terminalen där dotnet run körs, med klassnamnet framför.

Samma sak som @inject, på ett annat ställe

En komponent ber om sina tjänster med @inject. En vanlig klass kan inte det – den ber i stället genom sin konstruktor. Det är samma mekanism: du säger vad du behöver, och ramverket skickar in det när objektet skapas.

Ingen av dem skapar något med new. Det är hela idén med dependency injection: den som behöver något ber om det, och någon annan bestämmer vad som levereras.

59. Uträkningen lämnar komponenten

Medel · tränar: gränsen mellan presentation och logik

Given kod, en komponent som räknar själv:

<p>Snitt: @Snitt().ToString("0.0")</p>

@code {
    private List<int> tal = new() { 4, 8, 15, 16, 23 };

    private double Snitt()
    {
        int summa = 0;

        foreach (var t in tal)
        {
            summa = summa + t;
        }

        return (double)summa / tal.Count;
    }
}

Flytta både listan och uträkningen till en tjänst bakom ett gränssnitt.

Klart när: komponenten innehåller ingen foreach och ingen lista, och visar samma siffra som förut.

Lägg märke till vad som inte ska flytta: .ToString("0.0") stannar i komponenten. Antalet decimaler är utseende.

61. Vem väljer ut posterna?

Svår · tränar: att skilja vilka från hur

Given kod, en sida som filtrerar:

@code {
    private List<Film> visade = new();

    protected override async Task OnInitializedAsync()
    {
        List<Film> alla = await Arkivet.HamtaAllaAsync();

        foreach (var film in alla)
        {
            if (film.Betyg >= 4)
            {
                visade.Add(film);
            }
        }
    }
}

Urvalet hör inte hemma i komponenten. Flytta det.

Klart när: sidan har ingen foreach och inget if, och tjänsten har en metod vars namn säger vad urvalet är.

Det här är exakt det som sänker uppgiften på C

Koden ovan ser oskyldig ut. Den bygger, den fungerar, och den kräver ingen ansträngning att skriva. Men den betyder att komponenten bestämmer vad ett bra betyg är – och nästa sida som vill visa samma urval måste upprepa villkoret.

Metodnamnet är halva övningen. HamtaAsync säger ingenting. HamtaHogtBetygsattaAsync säger vad urvalet är, och gör det möjligt att ändra villkoret på ett enda ställe.
